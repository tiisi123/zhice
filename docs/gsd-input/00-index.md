# GSD Intake: 智策

## 使用方式

请在需求澄清阶段先阅读本文件，并把下列资料作为现有事实来源。不要重新发散定义产品；先从已有设计、原型和说明中提取需求、约束、非目标、风险和待澄清问题。

阅读顺序：先按"权威输入优先级"读 1→4 建立全貌，再用"资料索引"按目录补全细节，最后用"需要 GSD 优先澄清的问题"收敛 v1 边界。

---

## 当前目标

把已有设计、原型与改造意图整理成可执行的 GSD 里程碑：

- 先澄清需求边界（v1 范围 vs 后续 Phase）
- 生成或更新 `.gsd/PROJECT.md`
- 生成或更新 `.gsd/REQUIREMENTS.md`
- 形成第一个可交付里程碑
- 不要直接进入实现

GSD 拆解必须基于"原型已落地 → 改造意图 → PRD 缺口"的差量，而不是把 PRD 57 个功能点重新规划一遍。

## 已知非目标

来自 PRD §2.2、实施方案 §一以及 `prototype/DEPLOY.md`：

- 暂不做：实盘交易下单、资讯内容生产、通用金融搜索、KYC 认证、用户讨论区、移动端、港股 / 美股
- 暂不支持：多 worker 横向扩展（SQLite + 内存限频，建议单 worker 部署；并发商业化前需评估 Postgres + Redis）
- 暂不开放：真实收款入口（支付仍是 mock，`DEBUG=false` 时 `/api/payment/order` 返回 403；未接微信/支付宝真实下单与回调验签前不得公开商业化）
- 暂保留 mock：成长分析、价值分析、估值（等待接入真实财务数据源），但必须通过 `source` / `data_status` / `mock` 字段显式上报，**禁止静默降级**
- 暂不重新引入：XGT 作为短线默认数据源（短线默认必须用 KPL）
- 暂不上线：策略社区、Agent 市场（PRD P2，留待 Phase 5+）

## 需要 GSD 优先澄清的问题

下列问题是基于 PRD ↔ 原型 ↔ 改造意图三方对照得出的最大差量。GSD 在拆 v1 范围前必须先收敛这些问题。

### A. 范围与里程碑

1. **v1 是"原型加固上线"还是"按 PRD 重建"？** 原型已落地约 14 个页面、5 个 Agent、4 类 connector。建议 v1 锁定为"短线/热点 + 工具基础"加固上线，成长/价值与 4 风格全覆盖留到后续 Phase。
2. **PRD 的"4 种投资风格"如何与原型的"3 大板块"对齐？** 原型导航是短线/热点 + 成长/价值 + 工具；PRD §4.4 按打板/主题/成长/价值 4 风格切分。是否将 4 风格降级为板块内部的视图模式？
3. **`prototype/docs/` 下 5 份"产品改造方案"哪几份纳入 v1 必做？** 三大板块导航改造、短线热点改进、工具改造、成长/价值改造、用户/商业化风险闭环——需明确"v1 必做 / v1 可选 / v2 推迟"归类。

### B. 商业化与合规闸门

4. **v1 是"邀请码内测"还是"真实付费上线"？** `用户与商业化风险清单.md` 列出 S1 风险：`ZHICE_JWT_SECRET` 强校验、支付真实接入、报告归档可见性、会员权益服务端权限矩阵。如果走真实付费，这些必须全部闭环。
5. **AI 输出合规话术由谁拟定、何时给到？** PRD §7.3 LQ-01 / LQ-02（AI 是否构成荐股、免责声明措辞）尚无结论，会影响所有 AI Agent 输出层文案。

### C. 数据与降级策略

6. **"不静默降级 mock"如何与"成长/价值仍是 mock"共存？** `01-协作规范.md` 与 `04-数据源治理规范.md` 要求实时金融数据不得静默降级；但 `DEPLOY.md` 显示成长/价值/估值仍是 mock。v1 是否统一通过 `data_status` / `mock` 字段显式上报来共存？
7. **回测引擎在 TuShare 不可用时的蒙特卡洛降级是否保留？** `DEPLOY.md` 提到自动切换蒙特卡洛；需确认是否符合"不静默降级"口径，以及前端是否需要统一的降级提示样式。

### D. 质量与验收

8. **v1 上线门禁包含哪些项？** `上线测试问题清单.md` 给出 R1-001 ~ R1-006；至少需明确：构建警告是否阻断、E2E（Playwright/Cypress）是否必须、三轮测试 + 修复 + 剩余风险闭环文档是否必须。
9. **UI 一致性的硬约束是什么？** `raw/quicktiny-录屏拆解分析.md` 与 `三大板块导航改造规范.md` 提出"扁平导航 ≤ 2 级"、"暗色图表"、"就地展开 / 不跳转"、"Tab 缓存不丢状态" 等；需固化为前端验收清单条目。

### E. 多 Agent 协作

10. **GSD 里程碑是否沿用 `09-多Agent任务拆分与启动清单.md` 的角色与共享文件规则？** 涉及 `apps/api/main.py`、`apps/web/src/App.tsx`、`packages/shared/types.py`、`packages/connectors/registry.py` 等共享文件的修改边界与并行 Agent 上限。
