## 三、分阶段详细实施方案

---

### Phase 0：领域建模与数据底座（第 1-2 周）

**目标**：把 PRD 转成可开发的领域模型，旧接口能力抽成稳定层。

#### 产出物
1. 统一实体模型：股票、题材、板块、事件、异动、涨停原因、资金流、策略、回测结果、报告
2. 指标口径文档：情绪分、题材热度、龙头/梯队、风险标签、次日观察池
3. 数据源盘点表：kpl/xgt 接口清单、字段映射、缺失项
4. 合规边界文案：免责声明模板

#### 功能点

| # | 任务 | 详细内容 |
|---|------|---------|
| T-01 | **数据接入统一层** | 为 kpl、xgt 建立 connector；统一响应格式 source/raw/pulled_at/trade_date/entity_type/payload；股票代码标准化；时间戳/交易日统一；题材/板块ID映射；涨停原因/异动类型枚举统一 |
| - | 复用旧项目 | 从 `PySise6Code/daban_fastapi/app/api/v1/kpl/kpl_server.py` 抽取请求参数/headers/cookies；从 `common.py` 抽取字段映射逻辑；从 `xgt_router.py` 抽取热点/涨停接口 |
| - | 规避旧问题 | 不继承 `database.py` 硬编码凭据；不继承 `kpl_router.py` 中硬编码 UserID/Token；所有密钥外置配置 |

#### 目录结构初始化

```
智策AI/
├── apps/
│   ├── web/                 # React + TypeScript 前端
│   └── api/                 # FastAPI 后端
├── packages/
│   ├── connectors/          # kpl/ xgt/ (后续 ths/dfcf/jygs/tdx)
│   ├── normalizers/         # 字段统一/代码标准化/枚举统一
│   ├── features/            # 情绪分/题材热度/龙头识别/资金异动/K线标签
│   ├── backtest/            # DSL schema/策略执行/结果评估
│   └── shared/              # types/枚举/时间工具/常量
└── docs/                    # 领域模型/口径文档/合规文案
```

### 首期（Phase 0-2）：kpl + xgt

### 扩展期（Phase 3+）：逐步接入

| 数据源 | 提供能力 | 优先级 |
|--------|---------|--------|
| **ths（同花顺）** | 龙虎榜/涨停封单深度/资金流向 | Phase 3 |
| **dfcf（东方财富）** | 财报/公告/研报/估值数据 | Phase 4 |
| **jygs（聚源）** | 行业景气度/宏观数据 | Phase 4 |
| **tdx（通达信）** | K线历史数据/技术指标 | Phase 2(回测用) |

### 复用分级

| 级别 | 内容 | 处理方式 |
|------|------|---------|
| **直接复用** | 三方接口请求参数/headers/cookies/字段映射/部分解析函数 | 提取到 connectors |
| **重构后复用** | router聚合逻辑/数据清洗/题材涨停业务口径 | 提取到 normalizers + features |
| **不复用** | PySide6页面/旧MVC/硬编码配置/直接SQL | 全部重写 |
