## UAT-1: 短线真数据 e2e

**目标**：验证短线核心链路端到端可用——从登录到 KPL 实时数据展示、题材工坊浏览、AI Copilot 交互。

### 前置条件

- staging 环境已部署最新 main 分支
- KPL Cookie 已通过管理后台配置（`POST /api/admin/kpl-cookie`）
- 业主拥有有效邀请码或已注册账号

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 打开 staging 域名，进入登录页 | 显示登录表单（用户名 / 密码 / 邀请码输入框） |
| 2 | 使用邀请码注册或已有账号登录 | 跳转至首页或盘中盯盘页 |
| 3 | 导航至「盘中盯盘」页 | 页面渲染，DataStatusBadge 显示 KPL 数据源状态为可用 |
| 4 | 确认 KPL 实时数据 | 涨停/跌停/连板等 KPL 指标有真实数值（非空/非 mock） |
| 5 | 导航至「题材工坊」 | 页面加载，4 个 Tab（热点事件/题材板块/板块轮动/情绪周期）可切换 |
| 6 | 点击任意题材卡片 | 题材详情弹出，含关联股票列表 |
| 7 | 点击 AI Copilot 图标 | Copilot 面板打开，AIBadge（`AI 辅助生成`）可见 |
| 8 | 输入一个简单问题（如"今日涨停分析"） | AI 返回响应（可能耗时数秒），内容包含股票代码或市场分析 |

### 签字

- [ ] **UAT-1 通过** — 业主确认短线真数据链路端到端可用

## UAT-2: 商业化闸门 e2e

**目标**：验证免费用户访问付费功能时的拦截链路——403 → PaywallModal → 升级 → 支付页面返回"内测中"。

### 前置条件

- 使用一个**非 VIP** 账号登录
- staging `DEBUG=false`（生产模式）

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 登录免费账号 | 登录成功，侧边栏显示普通权限 |
| 2 | 访问一个需要 VIP 的接口（如高级策略回测） | 后端返回 403 Forbidden |
| 3 | 前端弹出 PaywallModal | 模态框显示 VIP 功能说明和升级按钮 |
| 4 | 点击"升级会员" | 跳转至 checkout / 支付页面 |
| 5 | 确认支付入口状态 | 页面显示 403 或"内测中，暂未开放"提示（`DEBUG=false` 时不允许真实支付） |

### 签字

- [ ] **UAT-2 通过** — 业主确认商业化闸门拦截链路正确

## UAT-3: 数据状态契约 e2e

**目标**：验证数据源异常时的降级展示和告警邮件——错误 Token 触发 fallback/unavailable badge，30 分钟内收到告警邮件。

### 前置条件

- staging 环境 SMTP 配置正确（`SMTP_HOST/PORT/USER/PASSWORD/FROM/TO`）
- 管理员可临时修改环境变量

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 将 `TUSHARE_TOKEN` 改为错误值，重启 API | API 正常启动（不因单个数据源失败而崩溃） |
| 2 | 访问依赖 TuShare 的页面（如估值分析） | DataStatusBadge 显示"不可用"或 fallback 状态 |
| 3 | 恢复正确 `TUSHARE_TOKEN`，重启 | 数据恢复正常，badge 显示可用 |
| 4 | 将 KPL Cookie 改为错误值，重启 API | API 正常启动 |
| 5 | 访问盘中盯盘页 | 页面显示"数据源不可用"提示 |
| 6 | 等待 ≤30 分钟 | 业主邮箱收到 KPL 健康告警邮件（`system_alerts kind='kpl_health'`） |
| 7 | 恢复正确 KPL Cookie，重启 | 数据恢复，收到恢复邮件 |

### 签字

- [ ] **UAT-3 通过** — 业主确认数据状态契约和告警链路正确

## UAT-4: 策略工坊真改造 e2e

**目标**：验证策略回测的确定性（相同输入两次结果一致）和参数敏感性（改变阈值产生不同交易）。

### 前置条件

- 登录有策略回测权限的账号
- TuShare 数据源可用

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 进入「策略工坊」页面 | 页面加载，显示 DSL 编辑器和回测控制面板 |
| 2 | 使用默认策略 DSL，点击"运行回测" | 回测完成，显示交易列表和收益曲线 |
| 3 | 记录交易笔数和总收益 | 记录值 A |
| 4 | 不修改任何参数，再次点击"运行回测" | 回测完成 |
| 5 | 对比两次结果 | 交易笔数和总收益**完全一致**（确定性验证） |
| 6 | 修改选股阈值（如 `select_threshold` 从 0.7 改为 0.5） | — |
| 7 | 点击"运行回测" | 回测完成 |
| 8 | 对比与步骤 2 的结果 | 交易笔数或个股组合**不同**（参数敏感性验证） |

### 签字

- [ ] **UAT-4 通过** — 业主确认策略回测确定性和参数敏感性

## UAT-5: 合规留证 e2e

**目标**：验证注册协议和支付协议的强制签署留证——用户必须勾选后才能继续，时间戳写入数据库。

### 前置条件

- 使用一个**全新账号**（未注册）
- 管理员可查询数据库

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 打开注册页面 | 显示注册表单 |
| 2 | 填写信息但**不勾选**服务协议 | 注册按钮不可点击 或 提交后提示"请先同意服务协议" |
| 3 | 弹出 RegisterTermsModal | 模态框不可关闭（`closable=false + maskClosable=false + keyboard=false`） |
| 4 | 勾选协议 checkbox | 注册按钮变为可点击 |
| 5 | 完成注册 | 注册成功，跳转至首页 |
| 6 | 查询数据库 `users` 表 | 新用户的 `terms_accepted_at` 字段有值（UTC 时间戳） |
| 7 | 导航至升级会员 / checkout 页面 | 显示 PaymentTermsModal（支付协议模态框） |
| 8 | 勾选支付协议 checkbox | — |
| 9 | 确认操作（支付页面会返回 403 "内测中"） | — |
| 10 | 查询数据库 | `payment_terms_accepted_at` 字段有值 |

### 签字

- [ ] **UAT-5 通过** — 业主确认合规留证链路完整
