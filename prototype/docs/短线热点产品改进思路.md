# 智策短线/热点产品改进思路

> 生成日期：2026-04-26  
> 范围：短线/热点业务模块、QuickTiny 截图参考、`daban` MySQL 数据库、本地 `zhice.db`、现有 Web 页面与 API 代码。  
> 目标：先形成整体产品改进方向，确认后再进入页面与数据层改造。

---

## 1. 结论摘要

当前「智策」已经具备较完整的短线/热点功能骨架，包括收盘复盘、盘中盯盘、情绪周期、题材板块、热点事件、炸板案例库、龙虎榜、轮动推演、个股分析、研究池、策略回测、AI Copilot 等。

但从短线交易用户视角看，现状更像“功能菜单集合”，还没有形成一条清晰的交易日主线。短线用户真正愿意付费的核心，不是更多表格，而是每天快速回答：

1. 今天市场能不能做？
2. 当前主线是谁？
3. 龙头、跟风、补涨、掉队分别在哪里？
4. 风险从哪里开始扩散？
5. 明天具体盯什么，什么条件做，什么条件放弃？

建议将短线/热点产品主线统一为：

```text
市场情绪 -> 主线题材 -> 龙头梯队 -> 风险验证 -> 次日计划
```

产品形态从“多个页面平铺”升级为“短线作战流程”。

## 2. 数据库与数据底座分析

### 2.1 远端 MySQL：`daban`

已通过 SSH 隧道连接远端 MySQL `daban`，执行了只读分析：

- `SHOW TABLES`
- 每表 `COUNT(*)`
- 每表 `SHOW FULL COLUMNS`
- 每表最多 `SELECT * LIMIT 100`

未在文档中保留敏感样本、密码、token、hash、策略代码全文。

当前 `daban` 共 6 张表：

| 表名 | 行数 | 主要字段 | 业务判断 |
|---|---:|---|---|
| `alembic_version` | 1 | `version_num` | 数据库迁移版本表 |
| `users` | 1 | `id`, `username`, `hashed_password`, `email`, `created_at`, `is_active`, `tushare_token` | 用户表，含敏感字段 |
| `market_data` | 242 | `id`, `symbol`, `date`, `open`, `high`, `low`, `close`, `volume`, `source`, `created_at`, `updated_at` | 日线行情 OHLCV，当前最有分析价值 |
| `strategies` | 1 | `id`, `user_id`, `name`, `description`, `code`, `status`, `created_at`, `updated_at`, `params_json` | 策略定义表 |
| `strategy_versions` | 1 | `id`, `strategy_id`, `version`, `code`, `name`, `created_at` | 策略版本表 |
| `backtest_tasks` | 1 | `id`, `user_id`, `strategy_id`, `symbol`, `start_date`, `end_date`, `initial_capital`, `status`, `result_json`, `created_at`, `updated_at`, `params_override_json` | 回测任务表 |

`market_data` 样例为类似 `000001.SZ` 的日线行情，字段覆盖开高低收、成交量、数据源 `tushare`。该库目前更偏“策略回测 + 日线行情基础库”，尚不是完整的短线情绪数据库。

当前未看到以下短线核心结构化表：

- 涨停池
- 炸板池
- 连板梯队
- 题材板块
- 热点事件
- 龙虎榜
- 分时异动
- 封单、撤单、开板时间线
- 次日溢价、接力成功率、断板反馈

本地库主要承担产品化能力：

| 表名 | 作用 |

### 2.3 数据底座改进建议

建议新增或沉淀以下核心表：

| 表 | 核心用途 |
|---|---|
| `daily_market_snapshot` | 每日情绪快照：涨停、炸板、最高板、封板率、情绪分 |
| `limit_up_pool` | 每日涨停池：个股、板数、涨停时间、封单、原因、题材 |
| `broken_pool` | 炸板池：炸板时间、回封、炸板原因、板数、题材 |
| `board_ladder_snapshot` | 连板天梯快照：N 板层级、龙头、跟风、晋级状态 |
| `theme_daily_snapshot` | 题材日快照：涨停家数、强度、资金、阶段、新旧 |
| `theme_event_link` | 热点事件到题材、个股的映射 |
| `dragon_tier_snapshot` | 龙头梯队：龙头、中军、跟风、补涨、掉队 |
| `longhu_snapshot` | 龙虎榜席位、买卖净额、席位风格 |
| `next_day_plan` | 次日观察池、触发条件、失效条件 |
| `similar_day_case` | 历史相似日与后续表现 |

短线产品若要生产级，必须把 connector/cache/mock 中的重要结果稳定落库，否则无法做历史对比、相似日、胜率统计、付费报告和个性化提醒。

## 3. QuickTiny 截图参考结论

`quicktiny_keyframes` 显示 QuickTiny 的核心可借鉴点：

### 3.1 连板天梯

截图开屏就是 A 股连板天梯，用户一眼判断：

- 今天最高板在哪里
- 连板层级是否完整
- 龙头是否断层
- 低位首板是否有补涨基础

智策应将“连板天梯”作为短线首页核心组件，而不是普通列表。

### 3.2 列表 + 详情联动

QuickTiny 多处呈现左侧列表、右侧详情、就地筛选、就地展开的工作台结构。短线用户需要高频切换，但不能丢上下文。

智策应减少页面跳转，重点使用：

- 行内展开
- 右侧详情抽屉
- 当前页筛选
- Tab 状态缓存
- 个股/题材联动高亮

### 3.3 多图表切换

截图中存在频繁图表切换，包括散点、柱状、曲线、热力图等。说明短线用户愿意看图，但图必须服务判断，不应只是展示。

智策可保留图表，但每张图都要回答一个明确问题：

- 情绪处于哪个阶段？
- 主线是否发酵到高潮？
- 高位风险是否扩散？
- 资金是否从 A 题材切到 B 题材？

### 3.4 核心工作台停留时间最长

录屏中最长停留的是大表格 + 图表组合的核心工作台。这说明专业用户真正付费的是“高效率工作台”，不是营销式页面，也不是单点功能。

智策需要把短线/热点收束为一个可反复使用的作战台。

## 4. 短线分析框架

### 4.1 五层判断模型

短线分析建议固定为五层：

```text
第一层：市场情绪
第二层：题材主线
第三层：龙头梯队
第四层：风险扩散
第五层：次日计划
```

### 4.2 市场情绪

核心指标：

- 涨停家数
- 炸板家数
- 炸板率
- 封板率
- 最高板
- 连板家数
- 首板数量
- 昨日涨停今日表现
- 跌停家数
- 高位断板数量

判断输出：

| 情绪阶段 | 产品表达 | 操作含义 |
---|---|---|
| 冰点 | 亏钱效应集中，等待修复 | 空仓或轻仓试错 |
| 修复 | 首板改善，炸板降低 | 小仓观察新主线 |
| 启动 | 主线明确，连板出现 | 关注 1 进 2、2 进 3 |
| 主升 | 龙头带队，梯队完整 | 跟随核心龙头和补涨 |
| 高潮 | 涨停多但分歧加大 | 不追高，观察兑现 |
| 退潮 | 高位炸板、断板扩散 | 降仓，回避接力 |

### 4.3 题材主线

题材强弱不能只看涨幅。建议综合：

- 涨停家数
- 连板数量
- 龙头高度
- 成分股扩散度
- 资金净流入
- 事件催化强度
- 首次出现时间
- 历史持续天数
- 是否出现中军
- 是否出现补涨

输出分层：

```text
主线题材
次主线题材
轮动题材
退潮题材
伪热点
```

### 4.4 龙头梯队

短线用户需要的是“梯队关系图”，不是孤立股票列表。

建议每个题材内输出：

- 龙头：高度最高、辨识度最高、带动性最强
- 中军：成交额大、趋势稳定、承接强
- 跟风：同题材低位涨停
- 补涨：龙头打开空间后出现的低位接力
- 掉队：断板、炸板、冲高回落

### 4.5 风险扩散

风险要前置，而不是放在报告末尾。

核心风险信号：

- 最高板炸板
- 2 板以上密集炸板
- 主线龙头断板
- 题材涨停减少但涨幅仍高
- 龙虎榜显示核心席位兑现
- 封板率下降
- 尾盘回落
- 昨日涨停低开低走

### 4.6 次日计划

收盘复盘最终必须沉淀为次日计划：

| 分类 | 含义 |
|---|---|
| 可打板 | 触发条件明确，题材和情绪共振 |
| 可低吸 | 龙头分歧但主线未坏 |
| 只观察 | 逻辑未验证或位置不舒服 |
| 规避 | 退潮、高位兑现、炸板扩散 |

每只观察标的都应给出：

- 关注原因
- 触发条件
- 失效条件
- 相关题材
- 对应风险

## 5. 现有短线/热点模块问题

当前一级菜单包括：

- 收盘复盘
- 盘中盯盘
- 情绪周期
- 题材板块
- 热点事件
- 炸板案例库
- 龙虎榜
- 轮动推演

问题不在于功能缺失，而在于主线分散。

### 5.1 页面过多，用户路径不清

短线用户进入产品后，不应先选择功能，而应直接进入工作流：

```text
今天发生了什么 -> 为什么发生 -> 哪些票代表主线 -> 风险是否出现 -> 明天怎么盯
```

### 5.2 表格偏多，图示不够

短线用户需要快速扫盘。表格适合承载明细，但不适合承载结论。

应优先使用：

- 连板天梯
- 情绪周期条
- 题材热力图
- 龙头梯队图
- 事件时间线
- 风险雷达
- 分时涨停/炸板节奏图

### 5.3 AI Copilot 还偏“问答按钮”

目前很多页面有 AI 追问按钮，但 AI 应从“被动问答”升级为“主动解释和决策辅助”。

建议 AI 在每个模块固定输出：

- 一句话结论
- 支撑证据
- 反向风险
- 明日观察
- 可追问问题

### 5.4 炸板和龙虎榜孤立

炸板案例库、龙虎榜不应只是独立页面。它们本质是：

- 炸板：风险验证
- 龙虎榜：资金验证

应该嵌入复盘、题材、个股、观察池中。

## 6. 信息架构重构建议

建议将短线/热点一级入口收敛为 4 个工作台。

### 6.1 收盘复盘

定位：每日总控台。

承载内容：

- 今日一句话结论
- 情绪温度
- 连板天梯
- 主线题材 Top3
- 龙头梯队
- 风险信号
- 次日观察池
- AI 复盘报告

用户目标：3 分钟完成收盘判断。

### 6.2 盘中盯盘

定位：实时作战台。

承载内容：

- 盘中温度
- 分时涨停节奏
- 炸板/回封时间线
- 龙头状态监控
- 异动流
- 观察池触发
- 高位风险预警

用户目标：盘中及时发现机会和风险。

### 6.3 题材工坊

定位：主线挖掘与推演。

合并：

- 题材板块
- 热点事件
- 轮动推演

承载内容：

- 主线 Top3
- 题材热力图
- 事件时间线
- 题材生命周期
- 产业链传导
- 龙头/中军/补涨
- 新旧题材识别
- A 启动后 B/C 跟涨概率

用户目标：知道资金正在炒什么，以及下一步可能炒什么。

### 6.4 验证中心

定位：风险、资金、历史规律验证。

合并：

- 炸板案例库
- 龙虎榜
- 历史相似日
- 策略回测相关短线模板

承载内容：

- 今日炸板归因
- 高位断板案例
- 龙虎榜席位行为
- 历史相似日后续走势
- 打板/接力/反包策略胜率

用户目标：验证直觉，减少主观冲动。

## 7. 页面设计建议

所有短线页面统一采用：

```text
顶部：一句话结论
中部：图示证据
底部：行动清单
右侧：AI Copilot / 详情抽屉
```

### 7.1 收盘复盘页

建议结构：

```text
[今日结论条]
情绪：回暖但高位分歧
主线：AI 算力、商业航天
风险：2 板以上炸板扩散
明日：看 2 进 3 承接

[情绪温度] [连板天梯] [主线题材]
[风险雷达] [资金验证] [次日观察池]
```

核心改造点：

- 顶部先给结论，不先堆卡片
- 连板天梯可视化优先级提升
- 题材和个股必须联动
- 风险信号前置
- 次日计划从报告里独立出来

### 7.2 盘中盯盘页

建议结构：

```text
[盘中温度 + 风险灯]
[分时涨停/炸板节奏图]
[龙头状态卡] [主线活跃卡]
[异动流] [观察池触发] [高位炸板]
```

核心改造点：

- 实时数据不只刷新表格，要刷新判断
- 炸板预警按严重程度分级
- 观察池触发要成为盘中主入口
- 龙头状态需要“正常、分歧、危险、确认退潮”等标签

### 7.3 情绪周期页

建议从折线图升级为周期地图：

```text
冰点 -> 修复 -> 启动 -> 主升 -> 高潮 -> 分歧 -> 退潮
                         ↑ 当前
```

核心改造点：

- 标出当前周期位置
- 展示近 5 日情绪路径
- 展示历史相似日
- 输出未来 1-3 日演化概率
- 给出仓位和打法建议，但保留合规免责声明

### 7.4 题材工坊页

建议结构：

```text
[主线 Top3]
[题材热力图]
[事件时间线]
[题材详情：定义、催化、龙头、中军、补涨、阶段]
[轮动推演：A 强 -> B/C 概率]
```

核心改造点：

- 题材详情不应只显示成分股
- 必须展示题材阶段：新出现、发酵、启动、高潮、退潮、反抽
- 必须区分新题材和老题材反抽
- 事件要和个股涨停原因挂钩

### 7.5 验证中心页

建议结构：

```text
[今日风险结论]
[炸板归因分布]
[高位断板案例]
[龙虎榜资金行为]
[历史相似日]
[策略胜率验证]
```

核心改造点：

- 炸板案例库从“案例列表”变成“风险归因”
- 龙虎榜从“席位排行”变成“资金是否支持主线”
- 历史相似日从“好看”变成“明日概率参考”

## 8. 付费化设计

用户愿意持续付费的核心是“每天离不开”。

### 8.1 免费层

适合展示：

- 基础行情
- 当日涨停数量
- 题材列表
- 简版情绪
- 延迟或限制次数的 AI 问答

### 8.2 标准会员

适合提供：

- 完整短线作战台
- 题材生命周期
- 炸板风险分析
- 次日观察池
- AI 收盘复盘
- 观察池提醒

### 8.3 专业会员

适合提供：

- 历史相似日
- 龙虎榜资金验证
- 策略胜率回测
- 个性化风格配置
- 盘中实时预警
- 专业报告归档
- 多维观察池

### 8.4 最强付费卖点

建议产品包装聚焦：

```text
每天 3 分钟看懂短线情绪，盘中自动盯主线风险，收盘生成明日作战计划。
```

## 9. 分阶段实施建议

### Phase 1：信息架构与收盘复盘改造

目标：让短线用户打开产品第一屏就知道今天怎么看。

任务：

- 重构短线/热点菜单
- 收盘复盘页顶部增加一句话结论
- 强化连板天梯
- 增加主线题材 Top3 与龙头梯队
- 增加风险雷达
- 抽出次日观察池

### Phase 2：题材工坊改造

目标：把题材、事件、轮动变成一个完整主线推演页。

任务：

- 合并题材板块、热点事件、轮动推演
- 题材热力图与事件时间线联动
- 增加题材阶段标签
- 增加龙头/中军/补涨分层
- 增加新旧题材识别

### Phase 3：盘中作战台改造

目标：盘中不仅看数据，还能收到机会和风险提示。

任务：

## 10. 优先确认事项

建议先确认以下方向，再进入代码改造：

1. 是否同意将短线/热点一级入口收敛为“收盘复盘、盘中盯盘、题材工坊、验证中心”四个工作台。
2. 是否同意第一期优先改造“收盘复盘”，把它做成短线用户第一入口。
3. 是否同意新增短线核心数据沉淀表，逐步替代 mock/cache/fallback。
4. 是否同意将炸板、龙虎榜从独立工具改为复盘/题材/个股中的验证能力。
5. 是否同意会员权益围绕“作战台、预警、AI 复盘、历史验证、次日计划”重新包装。

推荐第一刀：

```text
短线/热点导航重构 + 收盘复盘页改造
```

这是最容易让用户感知“产品变专业、能付费”的改动。

## 11. 页面内横向子模块导航

### 11.1 设计原则

短线/热点板块建议采用两级导航：

```text
左侧一级导航：进入哪个短线工作台
页面内横向导航：在当前工作台内完成哪一步分析
```

横向导航的作用不是再做一层菜单，而是把短线交易者的判断流程固定下来。

统一原则：

- 横向导航放在页面标题下方，吸顶或在滚动时保持可见。
- Tab 顺序必须符合交易判断流程，不按技术模块排序。
- 每个 Tab 都要回答一个明确问题。
- 横向导航建议 4-7 个项，超过 7 个放入“更多”。
- 切换 Tab 不应丢失筛选条件、日期、滚动位置和用户选择。
- 当前 Tab 下方只保留必要表格，优先用图示和卡片表达结论。

### 11.2 短线/热点工作台导航

左侧短线/热点一级入口建议：

```text
收盘复盘
盘中盯盘
题材工坊
验证中心
```

### 11.3 收盘复盘横向导航

页面目标：收盘后 3 分钟判断今天市场、主线、风险和明日计划。

横向导航：

```text
今日总览 | 情绪温度 | 连板天梯 | 主线题材 | 风险验证 | 次日计划
```

| Tab | 核心问题 | 推荐展示 |
|---|---|---|
| 今日总览 | 今天能不能做？ | 一句话结论、情绪等级、主线、风险、明日方向 |
| 情绪温度 | 市场情绪处于哪一段？ | 情绪仪表盘、涨停/炸板/封板率、近 5 日趋势 |
| 连板天梯 | 高度和梯队是否健康？ | 连板金字塔、晋级率、断板信号 |
| 主线题材 | 今天资金合力在哪？ | 主线 Top3、龙头/中军/补涨、题材热力 |
| 风险验证 | 风险是否扩散？ | 高位炸板、龙虎榜兑现、尾盘回落、资金背离 |
| 次日计划 | 明天盯什么？ | 可打板、可低吸、只观察、规避清单 |

专业建议：收盘复盘的默认 Tab 应是“今日总览”，但页面首屏要同时露出“次日计划”的摘要，让用户知道结论最终会落到行动。

### 11.4 盘中盯盘横向导航

页面目标：盘中快速发现机会和风险。

横向导航：

```text
盘中脉搏 | 龙头监控 | 异动流 | 炸板预警 | 观察池
```

| Tab | 核心问题 | 推荐展示 |
|---|---|---|
| 盘中脉搏 | 当前多空强度如何？ | 分时涨停/炸板节奏、封板率、最高板 |
| 龙头监控 | 龙头是否稳住？ | 龙头状态卡、分歧/转强/掉队标签 |
| 异动流 | 哪些标的突然变化？ | 时间轴、题材归因、AI 快速解释 |
| 炸板预警 | 风险是否集中爆发？ | 高位炸板、近 15 分钟炸板、回封情况 |
| 观察池 | 我的标的触发了吗？ | 研究池提醒、触发条件、失效条件 |

专业建议：盘中盯盘横向导航要短，避免用户盘中频繁找入口。风险相关 Tab 应有红色徽标提示，例如“炸板预警 5”。

### 11.5 题材工坊横向导航

页面目标：识别主线、理解催化、推演轮动。

横向导航：

```text
主线排行 | 事件时间线 | 题材生命周期 | 产业链传导 | 轮动推演 | 历史复盘
```

| Tab | 核心问题 | 推荐展示 |
|---|---|---|
| 主线排行 | 当前最强题材是谁？ | Top3 主线卡、热力图、龙头梯队 |
| 事件时间线 | 为什么炒？ | 新闻/政策/公告与题材联动 |
| 题材生命周期 | 处于发酵、启动、高潮还是退潮？ | 生命周期条、首次出现、持续天数 |
| 产业链传导 | 资金可能扩散到哪里？ | 上中下游图、受益环节 |
| 轮动推演 | A 强之后 B/C 是否接力？ | 历史概率、时滞、候选方向 |
| 历史复盘 | 过去类似题材如何演绎？ | 历史案例、相似周期 |

专业建议：题材工坊不应默认打开大表格，默认打开“主线排行”，右侧固定显示选中题材的 AI 摘要。

### 11.6 验证中心横向导航

页面目标：验证风险、资金和策略胜率。

横向导航：

```text
炸板归因 | 龙虎榜资金 | 历史相似日 | 策略胜率 | 案例库
```

| Tab | 核心问题 | 推荐展示 |
|---|---|---|
| 炸板归因 | 今天为什么失败？ | 原因分布、典型案例、高位断板 |
| 龙虎榜资金 | 主线是否被资金确认？ | 席位买卖、兑现/接力判断 |
| 历史相似日 | 历史上类似环境后来怎么走？ | 相似日列表、后 1/3/5 日走势 |
| 策略胜率 | 当前打法是否有效？ | 打板/接力/低吸策略表现 |
| 案例库 | 可以复盘哪些典型样本？ | 成功/失败案例、标签筛选 |

专业建议：验证中心的所有 Tab 都要能反向回流到“次日计划”，否则会变成独立工具。
