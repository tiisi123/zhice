# 分支与提交规范

## 分支模型

| 分支 | 用途 |
| --- | --- |
| `main` | 生产稳定分支 |
| `develop` | 日常集成分支 |
| `feature/<scope>-<name>` | 新功能 |
| `fix/<scope>-<name>` | 缺陷修复 |
| `hotfix/<scope>-<name>` | 生产紧急修复 |

## 命名示例

```text
feature/shortline-kpl-source
feature/web-header-cleanup
fix/intraday-empty-state
hotfix/market-source-kpl
```

## 提交格式

```text
type(scope): summary
```

常用类型：

```text
feat
fix
refactor
docs
test
chore
ci
```

常用范围：

```text
shortline
growth
value
web
api
auth
payment
connector
docs
ci
db
```

示例：

```text
feat(shortline): switch limit-up broken hot stocks to kpl
fix(web): remove duplicated page headers
docs(api): update shortline interface mapping
test(intraday): add realtime source contract checks
```

## PR 要求

- 单个 PR 优先控制在 300-800 行。
- 超过 1000 行需要拆分或说明原因。
- P0/P1 改动必须写风险点和回滚方案。
- 合并前必须说明验证命令和结果。
