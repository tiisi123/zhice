# 代码评审清单

## 必看项

- 是否改了不属于当前任务的文件。
- 是否新增或保留 mock 数据。
- 是否破坏已有 API 字段。
- 是否返回 `source`、`data_status`、`mock`。
- 是否处理空数据和错误状态。
- 是否更新接口文档。
- 是否涉及数据库 schema。
- 是否有回滚方案。
- 是否跑过必要检查命令。

## 风险分级

| 等级 | 范围 | 要求 |
| --- | --- | --- |
| P0 | 上线、数据源、支付、登录、权限 | 2 人 review，必须有回滚方案 |
| P1 | 核心页面、核心 API | 1 人 review，必须测试通过 |
| P2 | 样式、文案、小修复 | 快速 review |
| P3 | 文档 | 可快速合并 |

## 短线作战专项

- 是否真实走 KPL。
- 是否交易时间可用。
- 是否今日和历史日期逻辑正确。
- 是否返回实时更新时间。
- 是否 HTTP 与 WebSocket 一致。
- 是否调度器写入同一数据源。

## 前端专项

- 页面是否有 loading、empty、error。
- 是否出现重复头部。
- 是否存在硬编码 mock 文案。
- 是否把业务逻辑写进通用组件。
- 是否出现大量字段兜底，例如 `stock_code || SecurityCode || code`。

## 后端专项

- route 是否只做编排，不堆复杂业务逻辑。
- connector 是否只负责外部接口。
- 字段标准化是否在后端完成。
- 外部请求是否有超时和失败处理。
- 是否会在生产环境泄露调试信息。
