# 前端页面验收规范

## 通用验收

每个页面提交前必须检查：

- 页面可打开，刷新不白屏。
- loading 状态清晰。
- 真实数据状态正常。
- 空数据状态明确，不显示假数据。
- 接口错误状态可读。
- 表格和卡片不出现 `undefined`、`null`、`NaN`。
- 按钮、筛选、Tab、弹窗有反馈。
- 页面头部、标题、导航不重复。
- 移动端和窄屏没有明显遮挡。
- 控制台无关键报错。

## 短线作战额外验收

- 数量与 API 返回一致。
- 数据源可追踪，至少 API 返回 `source`。
- `mock` 必须为 `false`。
- 交易日期正确。
- 盘中刷新后数据不倒退。
- WebSocket 与 HTTP 数据不冲突。
- 空数据时显示真实空状态，不展示示例数据。

## 页面状态

页面必须覆盖：

| 状态 | 说明 |
| --- | --- |
| `loading` | 正在请求 |
| `ok` | 真实数据正常 |
| `empty` | 真实数据为空 |
| `error` | 请求或服务异常 |
| `stale` | 缓存或非实时数据 |

## 前后端边界

- `src/api` 只封装请求。
- `src/pages` 负责页面组合和业务展示。
- `src/components` 优先保持可复用，不直接请求业务接口。
- 前端只消费内部标准字段，不兼容外部源原始字段。
