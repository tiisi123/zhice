# 测试与上线规范

## 本地提交前检查

推荐一键检查：

```powershell
python scripts/check_before_pr.py
```

默认会拦截禁止提交的本地状态文件：

```text
data/**
.env
*.log
```

按 Issue 限制检查改动范围：

```powershell
python scripts/check_before_pr.py --allow "docs/process/**" --allow "scripts/**" --deny "apps/**" --deny "packages/**" --deny "data/**" --deny ".env"
```

`check_before_pr.py` 默认始终拦截 `data/**`、`.env`、`*.log`。其中 `data/zhice.db` 属于禁止提交文件，命中时不要删除或回滚，交给架构整合者处理。

包含本地 API 检查：

```powershell
python scripts/check_before_pr.py --api --api-base http://127.0.0.1:8000
```

包含前端构建：

```powershell
python scripts/check_before_pr.py --web
```

显式运行前端 lint：

```powershell
python scripts/check_before_pr.py --lint
```

说明：当前仓库存在历史全仓 lint 债务，`--lint` 适合专项治理或只查看新增问题；提交前硬门禁以 `--web` 构建通过为准。

后端：

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'; python -c "import apps.api.main; print('ok')"
```

前端：

```powershell
cd apps/web
npm run build
```

短期 PR 门禁以前端 build 为准。`npm run lint` 仍可本地辅助检查，但当前可能受历史全仓 lint 存量问题影响，不作为默认 CI 阻断项。

冒烟：

```powershell
python scripts/smoke_test.py
```

## CI 默认检查

GitHub Actions `Quality` workflow 默认在 `pull_request` 和 `main`、`develop` push 时运行：

- Python syntax check：`python scripts/check_python_syntax.py`
- 后端导入检查：`python -c "import apps.api.main; print('ok')"`
- mock 泄漏扫描：`python scripts/check_no_mock.py`
- 默认 PR 前检查：`python scripts/check_before_pr.py`
- 前端依赖安装：`cd apps/web && npm ci`
- 前端 build：`cd apps/web && npm run build`

CI 不依赖任何 secret，不做部署，不调用真实外部行情接口。默认 CI 不运行需要本地服务的 `check_api_contract.py`、`check_realtime_sources.py` 或 `smoke_test.py`。Issue 专属的 `--allow/--deny` 路径检查由本地或架构整合者手动运行，因为不同 Agent 的允许范围不同。

## 需要本地服务的检查

以下检查需要先启动本地 API 或 Web 服务，默认不放入 PR CI：

```powershell
python scripts/check_before_pr.py --api --api-base http://127.0.0.1:8000
python scripts/check_before_pr.py --web
python scripts/check_before_pr.py --api --web --smoke
```

- `check_api_contract.py`：需要可访问 API 服务，用于验证接口响应字段和状态。
- `check_realtime_sources.py`：需要可访问 API 服务，可能间接触达实时行情源，只能在人工确认数据源风险后运行。
- `smoke_test.py`：需要 API/Web 服务，用于端到端冒烟。
- 前端 lint：由 `python scripts/check_before_pr.py --lint` 在本地运行；如果需要升级为默认 CI，必须先清理现有 lint 存量问题。

GitHub Actions 提供 `workflow_dispatch` 手动入口，可在确认目标 API 可访问后运行服务依赖检查。不要把需要 secret、生产权限或真实外部行情接口的步骤设为默认 CI。

## 短线作战上线前检查

```powershell
python scripts/check_api_contract.py
python scripts/check_no_mock.py
python scripts/check_realtime_sources.py
```

## 上线流程

1. `develop` 合并完成。
2. 后端导入检查通过。
3. 前端 build 通过。
4. smoke test 通过。
5. 盘中真实接口检查通过。
6. 预发环境产品验收。
7. 合并 `main`。
8. 打 tag。
9. 部署生产。
10. 记录上线日志。

## 回滚要求

每次上线必须明确：

- 回滚到哪个 tag。
- 是否涉及数据库变更。
- 是否涉及数据源切换。
- 是否需要清缓存或重启调度器。
