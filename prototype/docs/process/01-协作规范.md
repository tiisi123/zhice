# 协作规范

## 基本原则

- `main` 分支必须始终可上线。
- 所有开发从任务卡开始，禁止只凭口头描述直接改核心链路。
- 每个业务模块必须有唯一 Owner，跨模块改动必须让相关 Owner review。
- 金融实时数据禁止静默降级为 mock；空数据必须返回真实空状态。
- 接口、页面、数据源、测试结果必须同步更新，不能只交代码。

## 模块 Owner

| 模块 | 责任范围 |
| --- | --- |
| 短线作战 | 盘中、复盘、情绪、题材、炸板、龙虎榜、KPL 数据 |
| 成长价值 | 成长、价值、财报、估值、ETF、研究页 |
| 用户体系 | 登录、会员、支付、权限、配额、研究池 |
| AI 能力 | AI 报告、个股洞察、Prompt、LLM 调用 |
| 前端体验 | 导航、布局、组件、页面一致性 |
| 工程质量 | CI、测试、上线、回滚、日志、监控 |

## 任务进入开发前必须明确

- 业务目标：为什么做。
- 页面范围：影响哪些页面。
- 接口范围：新增或修改哪些 API。
- 数据源：真实源是什么，是否允许缓存。
- 验收标准：怎样算完成。
- 风险与回滚：失败后怎么退。

## 禁止事项

- 禁止直接提交到 `main`。
- 禁止把无关重构混进业务需求。
- 禁止提交本地数据库、日志、临时缓存。
- 禁止前端直接适配外部原始字段。
- 禁止新增接口不写 `source`、`data_status`、`mock`。
