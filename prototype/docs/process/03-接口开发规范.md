# 接口开发规范

## 标准响应

核心业务接口统一返回：

```json
{
  "trade_date": "2026-04-27",
  "count": 0,
  "data": [],
  "source": "kpl",
  "data_status": "ok",
  "mock": false,
  "updated_at": "2026-04-27 10:30:00",
  "message": ""
}
```

## data_status 枚举

| 状态 | 含义 |
| --- | --- |
| `ok` | 真实数据正常 |
| `empty` | 真实接口返回空 |
| `partial` | 部分接口成功 |
| `stale` | 缓存数据，非实时 |
| `unavailable` | 数据源不可用 |
| `error` | 服务内部错误 |

## 字段命名

内部 API 统一使用：

```text
stock_code
stock_name
trade_date
change_rate
turnover_ratio
board_count
reason
combined_reason
first_plate_name
related_plates
source
data_status
mock
updated_at
```

外部字段必须在后端标准化，前端不直接处理 `SecurityCode`、`stockid`、`c`、`n` 等外部字段。

## 开发顺序

1. 更新接口映射文档。
2. 修改 connector 或 feature service。
3. 修改 route 响应。
4. 修改前端调用。
5. 增加契约检查。
6. 做页面验收。
