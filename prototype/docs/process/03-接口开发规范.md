# 接口开发规范

## 标准响应

核心业务接口统一返回（D004 锁定的契约 SSOT，参见 `.gsd/DECISIONS.md::D004`）：

```json
{
  "trade_date": "2026-04-27",
  "count": 0,
  "data": [],
  "source": "kpl",
  "data_status": "real",
  "mock": false,
  "updated_at": "2026-04-27 10:30:00",
  "message": ""
}
```

后端必须通过 `apps/api/utils/contract.py::wrap_contract(...)` 共享 helper 包装响应；它强制
ALLOWED_STATUS 6 值集合 + 一致性约束 + auto-empty 兜底。前端类型对齐
`apps/web/src/api/types.ts::DataStatus | ApiMeta`，UI 渲染统一走
`apps/web/src/components/DataStatusBadge.tsx`。

## data_status 枚举（D004 SSOT，6 值）

| 状态 | 含义 |
| --- | --- |
| `real` | 数据源直返成功 |
| `mock` | 演示/样例数据（与 `mock=true` 互为充要条件） |
| `fallback` | 主源失败但有降级数据（含 cache stale + Monte Carlo 降级） |
| `unavailable` | 数据源完全不可达（运维需排障） |
| `empty` | 数据源响应为空（区别于不可用） |
| `error` | 异常但已捕获（不抛 5xx） |

### 旧值映射（一次性迁移，禁止再生）

| 旧值 | 新值 | 说明 |
| --- | --- | --- |
| `ok` | `real` | 直返成功 |
| `stale` | `mock` 或 `fallback` | sample/演示路径 → `mock`；cache 过期/Monte Carlo 降级 → `fallback` |
| `partial` | `fallback` 或拆分 | 路由按语义自决；不再保留 `partial` 字面值 |

### 一致性约束

- `mock=true` ⟺ `data_status='mock'`，由 `wrap_contract` ValueError 阻断违规组合，
  并由 `prototype/scripts/check_api_contract.py` 在 CI 强制校验。
- `status='real'` 且 data 为空时，`wrap_contract` 自动改写为 `data_status='empty'`，
  让前端不需要再次判空。
- `data_status` 必须在 6 值集合内，超集由 `wrap_contract` raise ValueError 阻断。

豁免路由清单（控制流 / 协议异类，不返回 `data` 数据载荷）见
`.gsd/DECISIONS.md::D005`，落地在 `prototype/scripts/contract_endpoints.py::EXEMPT_ENDPOINTS`。

## 字段命名

内部 API 统一使用：

```text
stock_code
stock_name
trade_date
change_rate
turnover_ratio
board_count
reason
combined_reason
first_plate_name
related_plates
source
data_status
mock
updated_at
```

外部字段必须在后端标准化，前端不直接处理 `SecurityCode`、`stockid`、`c`、`n` 等外部字段。

## 开发顺序

1. 更新接口映射文档。
2. 修改 connector 或 feature service。
3. 修改 route 响应。
4. 修改前端调用。
5. 增加契约检查。
6. 做页面验收。
